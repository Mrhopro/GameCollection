# Game Collection

Консольний навчальний мініпроєкт на C++17 для обліку особистої колекції відеоігор. Застосунок дає змогу вручну додавати й редагувати записи, шукати, видаляти, сортувати та фільтрувати ігри, переглядати статистику, підключати профіль Steam і імпортувати доступну бібліотеку.

## Мета і призначення

Проєкт демонструє структури, класи, функції, цикли, динамічні масиви, рядки, умовні оператори та роботу з файлами. Це консольна програма без графічного інтерфейсу для дисципліни «Основи програмування».

## Технології

- C++17 і стандартна бібліотека.
- Visual Studio solution і проєкт MSBuild: GameCollection.sln та GameCollection.vcxproj.
- libcurl для HTTP-запитів.
- nlohmann/json для розбору відповіді Steam у пам’яті.
- Windows API для UTF-8 консолі.

## Структура

- src/main.cpp — одне головне меню та виклики простих функцій.
- src/Game.cpp і include/Game.h — запис гри та її досягнення.
- src/Collection.cpp і include/Collection.h — список ігор, додавання, вилучення та пошук.
- src/SteamClient.cpp і include/SteamClient.h — запити Steam Web API.
- src/BinaryStorage.cpp і include/BinaryStorage.h — читання та запис бінарних даних.
- data/collection.dat — файл колекції, створюється під час першого збереження.

## Залежності та збирання

Потрібні Visual Studio з компонентом Desktop development with C++. У проєкті вже підключені заголовки libcurl і nlohmann/json та DLL libcurl для x64. Використані libcurl 8.23.0 і nlohmann/json 3.12.0; їхні файли розміщені в каталогах dependencies/curl-msvc та include/nlohmann. Інші бібліотеки не потрібні.

Відкрийте GameCollection.sln, виберіть x64 і зберіть Debug або Release. Це звичайний Visual Studio-проєкт; CMake для проєкту не використовується. Після збирання Visual Studio копіює libcurl DLL у каталог програми.

## Налаштування Steam API Key

Для Web API потрібен Steam API Key. Не вставляйте ключ у вихідний код або файл даних. У Windows задайте змінну середовища STEAM_WEB_API_KEY перед запуском програми та перезапустіть консоль або Visual Studio.

## Функції програми

- Додавання, перегляд, пошук, редагування та видалення гри.
- Сортування за назвою; фільтрація за жанром, платформою, статусом проходження, діапазоном оцінок і станом встановлення.
- Статистика ігор, проходжень, розблокованих досягнень та середньої оцінки.
- Підключення через SteamID або vanity-посилання; OpenID відкриває браузер, приймає локальний callback на порту 43821 і перевіряє відповідь Steam.
- Імпорт доступної бібліотеки та оновлення назв уже імпортованих ігор.
- Окремий запит Steam Store пробує отримати жанр за AppID; якщо даних немає, жанр можна внести вручну.
- Перевірка локально встановлених ігор за файлами Steam та запуск установленої гри через протокол Steam.

Сканування читає libraryfolders.vdf і appmanifest_*.acf, які створює Steam, щоб знайти каталоги бібліотек та перевірити наявність установлених файлів. Програма не змінює ці файли й не копіює їх у власне сховище. Сканер знаходить тільки встановлені локально ігри, а не повний список придбаних ігор. Запуск передається клієнту Steam через посилання steam://run/AppID.

Steam API повертає лише дані, доступні за налаштуваннями приватності профілю. Бібліотека може бути недоступна або неповною. Досягнення залежать від підтримки конкретної гри та доступності статистики. Не можна вважати, що приватні дані доступні гарантовано. Навчальний прототип імпортує бібліотеку; повний імпорт досягнень потребує окремого виклику API для кожного AppID та обробки недоступних відповідей.

## Бінарне зберігання

Усі постійні дані застосунку зберігаються виключно у власному бінарному форматі. Поточна версія файла collection.dat має підпис GC02 і містить кількість записів, наступний ID, дані Steam-профілю та поля кожної гри, включно зі станом встановлення. Програма також читає попередній формат GC01 і трактує його ігри як не встановлені. Кожен рядок записується окремо: спочатку 32-бітна довжина, потім символи UTF-8. Числа та прапорці записуються окремими полями. Під час читання перевіряються підпис, довжини та межі кількостей.

Не використовуйте JSON, XML, SQLite чи звичайні текстові файли для постійного зберігання. JSON Steam API дозволено розбирати тільки в оперативній пам’яті; записувати його на диск заборонено. API-ключ у файлі даних не зберігається.

## Основні класи та функції для захисту

- Game зберігає назву, жанр, платформу, статус проходження, оцінку та досягнення. Геттери повертають поля, сеттери змінюють їх.
- Collection містить динамічний список, створює ID, додає, видаляє та шукає ігри.
- BinaryStorage окремо серіалізує кожне поле через потоки з ios::binary і перевіряє помилки.
- SteamClient формує HTTP-запити libcurl, обробляє JSON nlohmann у пам’яті та оновлює колекцію доступними даними.
- Steam OpenID визначає SteamID без API-ключа. Ключ потрібний для профільних ігрових запитів Steam Web API, наприклад імпорту бібліотеки й досягнень.
- main — єдина точка входу; налаштовує кодування консолі, показує меню та викликає потрібні функції.
